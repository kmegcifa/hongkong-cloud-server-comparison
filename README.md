## 香港云服务器该按哪几个指标挑

结论：大致按回程线路 > 带宽端口与流量口径 > CPU 是否超售 > 价格来挑。

香港机房线路分三档，对应价格不是一个量级：

1. **香港本地带宽**：便宜，适合面向香港本地或国际访客，大陆访问经常绕路。
2. **香港国际带宽**：中等价位，国际互联好，大陆方向看运气。
3. **CN2 / 9929 / CMIN2 回国直连**：贵，但晚高峰不容易恶化。普通香港线路白天飞快、晚上八点拥堵的情况并不少见。

再往下有几个容易忽略的细节：

- **流量单向还是双向计**。GoMami 香港 Turin 系列标的是单向流量（只计出站），同样标“1TB”，可用空间比双向计费大一倍。
- **端口是上限还是保证带宽**。2Gbps、5Gbps 是 VirtIO 端口上限，不是独享带宽。
- **CPU 是否超售**。共享核心和独享核心在数据库、编译这类场景里差别巨大。
- **用超流量后怎么处理**。限速、停机还是按 G 扣费，长期成本差很多。
- **退款窗口有多长**。买之前判断不了线路对不对，退款政策比参数表更实用。

GoMami 官方商店页逐项标了 VirtIO 端口、单向流量和 “China Mainland Optimized Pro”，香港 Turin 全系配 1 个 IPv4。第三方测评记录的香港 Turin 测试机网络归属为 AS36002，机房在葵涌（NKT），去程电信广州 4134 转香港 CTG、联通 4837 转 CUG、移动 9808 转 CMI，回程分别走 CTG、9929、CMIN2。多个来源引用的官方口径是香港到大陆主要城市 RTT 低于 50ms。

## Turin 和 Pulse 的差价，究竟买到了什么

Turin 比同档 Pulse 贵，Mini 和 Air 各贵 10 美元，Pro 贵 30 美元，Ultra 贵 100 美元。这笔钱买的是 CPU 代际、硬盘规格和端口，线路不在其中。

两条线的三网回程配置一致：电信 CN2 / 联通 9929 / 移动 CMIN2。业务核心诉求是“大陆访问要稳、延迟低”，Pulse 已经能满足；差价花在别处：

- **CPU**：Turin 的 EPYC 9575F 是 Zen 5，最高 5GHz。第三方测评在 6 核 Turin 测试机上跑出 Geekbench 6 单核 2789、多核 11608；Pulse 的 EPYC 7763 在另一份测评里单核约 1100+ 分。两个数字来自不同机器、不同时间，不能直接当同条件对比，但单核差距的量级是清楚的。
- **存储**：Turin 起步 100GB NVMe，Pulse 起步 40GB，且 Turin 用 PCIe Gen5 U.2 盘。第三方在 Turin 6 核机上测得 fio 4K 随机读写约 557/558 MB/s（约 139k IOPS），1M 顺序读写约 1.30/1.38 GB/s。
- **端口**：Turin 起步 2Gbps，Pulse 的 Nano 到 Air 只有 1Gbps，Pro 才升到 3Gbps。

数据库、游戏服、单线程响应敏感的 API，Turin 的差价付得过去；纯 WordPress 博客、轻量建站，Pulse 跑得动。测评社区对 Turin 的总结是“除了贵这个缺点全是优点”，反过来理解也成立：贵是真的贵。

## 价目表上看不到的限制，买前必须知道

有四条会直接影响使用体验，且都不出现在套餐表格里。

**移动方向上行为 QoS，部分省份会断流。** 对香港 Turin.Mini 的多点测速显示，广东移动 1Gbps 环境下上行平均约 38 Mbit/s、下行约 284 Mbit/s；武汉移动上行约 37.3、下行约 549；宁波移动上行约 41.0、下行约 653。下行没问题，上行被压得明显。同一测评的分运营商结论：电信用户香港≈日本>新加坡，联通用户香港>日本>新加坡，移动用户新加坡>日本≈香港。要大量上传（直播推流、大文件同步、批量图床），香港 Turin 不是最优解。

**防火墙行为不稳定，会削单线程速度。** 有测评记录单线程国内测速只跑到 200Mbps（套餐标的是 G 口），换直连 HTTPS 又能跑满；用 nftables 做 TCP 转发时只有 20Mbps。原文的说法是“防火墙就是这样，就像个黑盒，你永远不知道会触发什么禁制”。打算架代理、做端口转发或跑非标准协议，预留试错时间。

**DDoS 防护分两档，触发黑洞时无法人工干预。** 官方文档写明所有实例默认带尽力而为（Best-Effort）的免费防护，系统自动检测并做基础清洗，不用手动配置；更高一档的 600 Gbps 清洗属于付费增值服务，费用需联系客服确认。真正需要留意的是黑洞机制：当攻击影响到同网段其他客户，系统会直接对该实例 IP 执行 null route，时长 30 到 60 分钟、自动解封、无法人工解除，期间所有进出流量被丢弃。文档列出的防护范围覆盖 UDP Flood、SYN Flood、ACK Flood、ICMP Flood、DNS 放大、NTP 放大，以及 HTTP Flood、CC、Slowloris 这类 L7 攻击，L7 策略会因节点不同有差异。

**超流量不限速到死，但会掉到 20 KB/s。** 流量跑完后限速到 20 KB/s，到下一个计费周期自动重置，不额外扣费也不停机；需要时可以单独加购流量包，不必为了一点超额去升整档。

还有两个小细节：iperf3 默认的 5201 端口被封，自测要换端口；测试机显示 IPv4 在线、IPv6 离线，需要 IPv6 的建站方案先确认能否开通。

## 按场景对号入座

先看你的业务是否需要大量上行，这一条就能筛掉一半选项。

- **只跑一个 WordPress 博客、日 IP 三位数**：香港 Pulse.Mini，$59/月，4GB 内存跑 CMS 不至于捉襟见肘。再降到 Nano，2GB 装几个插件就吃紧。
- **外贸站、面向大陆客户的业务系统**：香港 Turin.Mini，$69/月。三网回程直连，1TB 单向流量够小中型站点用，单核也能撑后台。
- **MySQL 单线程查询、游戏服务端、低延迟交易逻辑**：Turin 系列，Zen 5 的单核是这条线的核心卖点。
- **要装 Windows 的远程桌面或 ERP**：Turin.Pro 及以上，官方标 Windows-ready；Pulse.Pro 也有 Windows 就绪标注，价格更低但 CPU 更老。
- **多容器、多站点托管、多进程并行**：Pulse.Pro 或 Pulse.Ultra，8 到 16 核堆核心数更划算，单核频率低一些可以接受。
- **大量上行数据（直播推流、大文件同步）**：先别下单。移动方向上行的 QoS 是已知问题，用 Looking Glass 测过自己的线路再决定。
